# FastESM

**FastESM** is an open-source **Enterprise Service Management (ESM)** platform
built with [FastHTML](https://fastht.ml) — Python-first, server-side, HTMX-driven,
no JavaScript framework. It takes the ITSM ticket/SLA model and extends it across
**every department** (IT, HR, Facilities, Finance): a **service catalog** you
browse like a webshop, **request orchestration** with approval → fulfilment
workflows and live SLA timers, **role-based** views (Employee / Agent / Manager /
Admin), a **knowledge base**, a config-driven **form & workflow designer**,
Plotly dashboards, and a grounded AI assistant.

*One front door for every service your organisation runs.* Runs on port **5015**.

> **Synthetic data only — no PII.** Everything ships and runs on deterministic,
> fully synthetic data generated by `seed.py`.

Part of the **FastGov** suite — a family of MIT-licensed, self-hostable
government/enterprise apps (FastHelpdesk, FastCRM, FastHRM, FastERP, …).
FastESM extends the FastHelpdesk ticket/SLA engine into full cross-department ESM.

## Digital sovereignty by design

FastESM is the answer to procurement questions that begin with *"where does our
data go, and who owns the platform?"*

- **EU-hostable, self-hostable.** A single Python process and one SQLite file.
  Run it on a laptop, a VM in your own datacentre, or any EU cloud — no managed
  SaaS, no US-hosted control plane, no phone-home.
- **MIT-licensed, no lock-in.** Copyright Predictive Labs Ltd, MIT. Fork it, audit
  it, extend it, keep it. Your service catalog, forms and workflows are plain data
  you can export at any time — not a proprietary format.
- **No mandatory third parties.** The AI assistant is optional and pluggable
  (xAI / OpenAI / Anthropic / Google, or none). With no API key the whole app still
  works and the assistant answers from your own database via slash-commands. You
  choose the model provider — or run none.
- **Transparent by construction.** Server-rendered HTML, a readable schema, and a
  workflow layer that is configuration, not opaque code.

This is the wedge against closed, cloud-locked ESM incumbents: the same
service-management capability, on infrastructure you control.

## Quickstart (native)

```bash
python -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
cp .env.sample .env          # optional — add an LLM key for free-form AI chat
.venv/bin/python web_app.py  # http://localhost:5015  (self-seeds on first boot)
```

Login: `admin@fastesm.example` / `FastESM2026$` (override in `.env`). After login,
**pick a role** (Employee / Agent / Manager / Admin) — the app adapts.
Rebuild demo data: `.venv/bin/python seed.py`.

## Run with Docker

```bash
docker compose up --build      # http://localhost:5015
```

`Dockerfile` (python:3.12-slim, port 5015) seeds on first boot;
`docker-compose.yml` mounts a `fastesm-data` volume at `/data` so the SQLite DB
survives rebuilds.

## Module tour

- **Service Catalog** (`/catalog`) — browse services by department and request one
  through a form **rendered from JSON** (no code per service). Cart-less webshop:
  each request becomes a tracked order.
- **My Requests** (`/my-requests`) — an employee's orders with live status & SLA.
- **Request Queue** (`/requests`) — filter by status & department; open any request
  for its conversation, submitted form data, **live SLA timers**, and activity log.
- **Approvals** (`/approvals`) — the manager's gate: approve or reject requests for
  services flagged *approval required* before they reach fulfilment.
- **Form & Workflow Designer** (`/designer`) — edit a service's JSON intake form,
  SLA and approval flag with a live preview. Configuration is data, not code.
- **People & Departments** (`/people`) — RBAC roles and per-department backlog.
- **Dashboard** (`/`) — SLA/workload KPIs with **Plotly** charts (status donut,
  department bar) and an "SLA at risk" worklist.
- **Knowledge Base** (`/kb`) — self-service articles by category.
- **AI Assistant** (right rail) — chat over a **live snapshot** of the queue.
  Plain-English questions stream from a configurable LLM; **slash-commands**
  (`/sla`, `/approvals`, `/requests`, `/priority`, `/catalog`, `/departments`,
  `/kb`, `/kpi`, `/help`) resolve instantly with **no API key**.

## RBAC

Post-login you choose a lens; the left nav and available actions adapt:

| Role | Sees |
|------|------|
| **Employee** | Service Catalog · My Requests · Knowledge Base · AI |
| **Agent** | Dashboard · Request Queue · Catalog · KB · AI |
| **Manager** | Dashboard · Approvals · Request Queue · KB · AI |
| **Admin** | Everything + Form & Workflow Designer + People & Departments |

Switch roles anytime from the top-bar switcher.

## Request workflow & SLA engine

Requests flow **Submitted → (Pending Approval → Approved) → In Progress →
Fulfilled** (or Rejected / Cancelled). Each priority (Urgent / High / Medium / Low)
has a first-response target; each **catalog service** carries its own fulfilment
SLA (hours). FastESM computes each open request's live SLA state against the clock
and renders a badge — *Response due in 2h*, *Fulfilment overdue 1d* — so the queue
surfaces what needs attention first.

## Configuration

`.env` (see `.env.sample`). Free-form AI chat needs one provider:

```ini
MODEL_PROVIDER=xai          # xai | openai | anthropic | google
MODEL_NAME=grok-4-1-fast-reasoning
XAI_API_KEY=...
```

Without a key the whole app still works and slash-commands answer from SQLite.

## Architecture

```
web_app.py        routes, auth, RBAC role-select, catalog submit, SSE chat, boot
db.py             SQLite schema + SLA engine + catalog/request/approval helpers
seed.py           deterministic synthetic-data generator (departments, catalog, requests)
web/layout.py     3-pane shell, role-aware nav, CSS, chat JS
web/views.py      page renderers (dashboard, catalog, requests, approvals, designer …)
web/ai.py         slash-commands + multi-provider streaming chat
```
